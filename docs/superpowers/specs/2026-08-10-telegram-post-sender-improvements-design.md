# Telegram Post Sender — дизайн улучшений

Дата: 2026-08-10

## Контекст

Проект — одна страница `index.html` (689 строк, vanilla JS), которая шлёт посты в Telegram
через Bot API прямо из браузера, без backend. Главная ценность: скачал один файл, открыл,
работаешь. Эту ценность улучшения не должны ломать.

## Найденные дефекты

1. **Поле `style` у inline-кнопки не существует в Bot API.** `buildReplyMarkup` кладёт в
   кнопку `style: 'primary' | 'success' | 'danger'`. Telegram такого поля не знает: в лучшем
   случае игнорирует, в худшем — возвращает ошибку парсинга разметки, и пост не уходит.
2. **MarkdownV2 работает наоборот.** `escapeMarkdownV2` экранирует все спецсимволы, включая
   `*` и `_`. Пользователь выбирает MarkdownV2 ради форматирования и получает текст со слэшами.
3. **Подпись теряется в смешанном альбоме.** Условия расстановки `caption` устроены так, что
   при комбинации «URL + файл» подпись не попадает ни в один элемент `media`.
4. **429 не обрабатывается.** `retry_after` из ответа Telegram игнорируется, пост теряется.
   При этом фиксированная пауза 5–7 секунд тормозит рассылку там, где лимит не достигнут.
5. **Повторный клик по «Отправить»** запускает параллельный цикл рассылки в те же чаты.
6. **Лимиты Telegram не проверяются:** текст 4096, подпись 1024, альбом 2–10 медиа.
7. **Токен в cookie.** Cookie уходит в каждом HTTP-запросе к домену. При открытии страницы
   не через `file://` (например, GitHub Pages) токен бота утекает на хостинг в заголовках.

## Решения

### Архитектура

Файл остаётся один. Внутри `<script>` код разбивается на слои с явными границами:

| Слой | Ответственность |
| --- | --- |
| `Store` | localStorage, миграция токена из cookie, экспорт/импорт |
| `Api` | HTTP к Telegram: retry, `retry_after`, отмена через `AbortController` |
| `Markup` | `parse_mode`: экранирование, вставка форматирования, рендер предпросмотра |
| `State` | chats, buttons, templates, draft — единственный источник правды |
| `Ui` | рендер DOM из состояния |
| `Sender` | очередь рассылки, прогресс, отмена |

Отвергнутые варианты: разбиение на отдельные `.js` (ES-модули не грузятся с `file://`,
а «скачай папку» хуже «скачай файл») и сборка через npm (превращает vanilla-проект в
проект, требующий Node — оверинжиниринг для этого размера).

### Кнопки

Поле `style` убирается из payload. Вместо него — выбор эмодзи-маркера, который
подставляется в начало текста кнопки. Это единственный способ визуально выделить
inline-кнопку средствами Bot API. Добавляются перестановка кнопок (↑/↓) и валидация URL.

### Форматирование

Авто-экранирование MarkdownV2 удаляется. Взамен:

- панель форматирования (жирный, курсив, подчёркнутый, зачёркнутый, спойлер, код,
  цитата, ссылка), вставляющая корректную разметку под выбранный `parse_mode`;
- отдельная кнопка «Экранировать спецсимволы» для случая, когда нужен литеральный текст;
- живой предпросмотр, показывающий результат рендера;
- расшифровка ошибок парсинга от Telegram в понятный текст.

### Отправка

- caption всегда ставится на первый элемент `media`, независимо от его источника;
- 429 → ждать `parameters.retry_after` и повторить (до 3 попыток); сетевая ошибка →
  повтор с экспоненциальной паузой;
- пауза между чатами настраивается (по умолчанию 3–5 с);
- кнопка «Отмена» прерывает очередь; «Отправить» блокируется на время рассылки;
- прогресс-бар и итоговая сводка «успешно / с ошибками».

### Типы контента

Добавляются `sendVideo` и `sendDocument`. В альбоме разрешается микс фото и видео
(`sendMediaGroup` это поддерживает). Добавляются опции `disable_notification`,
`protect_content`, `link_preview_options.is_disabled`.

### Хранение и безопасность

Токен переезжает в `localStorage`; существующий токен из cookie мигрирует автоматически,
cookie удаляется. Кнопка «Проверить» вызывает `getMe` и показывает имя бота. Если
`location.protocol !== 'file:'`, страница показывает предупреждение о рисках хостинга.

### UX

Названия чатов подтягиваются через `getChat` и показываются вместо числовых id.
Поля, не относящиеся к выбранному режиму, скрываются. Добавляются счётчик символов с
учётом лимита режима, автосохранение черновика, drag & drop файлов, экспорт/импорт
настроек в JSON, тёмная тема (авто + переключатель), sticky-предпросмотр поста в стиле
Telegram.

## Проверка

Ручной сценарий: отправка текста, фото по URL, фото файлом, видео, документа, альбома
из микса URL и файлов — с кнопками и без, в каждом `parse_mode`. Проверка отмены на
середине очереди и поведения при заведомо неверном chat_id.
